# 京都—大阪六日行程地图设计规格

## 目标

制作一个公开可访问、手机优先的静态行程地图，并部署到 GitHub Pages。页面帮助旅行者在途中快速确认当天路线、下一站、交通方式和关键票务提醒，而不是把行程做成不可调整的强制时间表。

成功标准：

- 手机上打开后，第一眼能看到当天地图、路线和下一站。
- D1–D6 可切换，每天地图与时间线同步更新。
- 每个地点可打开外部导航，关键地点可打开官方票务或详情链接。
- 地点与时间保存在独立数据文件中，后续可通过聊天修改后重新部署。
- 页面不展示航班订单号、护照、房间号、家庭住址等私人信息。

## 已确认事实与假设

- 旅行日期：2026年10月4日至10月9日；10月9日21:30从大阪起飞，10月10日00:40抵达香港。
- 京都住宿：GLANSIT KYOTO KAWARAMACHI，京都市中京区河原町通四条上る米屋町380-2。
- 大阪住宿：Grand Hostel LDK Osaka Shinsekai，2-7 Ebisunishi 3 Chome, Naniwa-ku, Osaka 556-0003。
- 视觉方向：已批准 A「地图优先」。
- 发布方式：GitHub Pages，页面公开访问。
- 修改方式：地点数据与界面代码分离；用户在聊天中提供增删改内容后重新部署，不在网页内加入登录或编辑后台。
- Day 2 和服店名称尚未提供。初版只显示“祇园和服妆造”日程项，不放置不准确的店铺坐标；后续收到店名或地址后补充地图标记。

## 信息架构

页面为单页静态应用：

1. 地图区：首屏上方约56%，显示当天地点、编号标记与行程路线。
2. 行程抽屉：首屏下方约44%，可上下拖动或展开，显示当天标题、路线摘要和时间线。
3. 日期切换：D1–D6 横向排列，选中后同时更新地图范围、路线和时间线。
4. 地点详情：点击标记或时间线项目，展开简短说明、交通提示、风险提示和链接。
5. 导航操作：每个地点提供“导航”；优先使用 Google Maps 通用链接，在不支持时退化为经纬度查询。
6. 关键提醒：花火票、环球影城门票、机场出发时间等只在相关日期中出现，不创建独立通知系统。

## 视觉系统

- 主色：京都深绿 `#173F2C`。
- 路线与当前站：朱红 `#E45D3C`。
- 地图背景：浅鼠尾草绿；界面表面使用纯白，不使用米白或奶油色。
- 字体：中文系统无衬线字体栈，标题粗体，控制文字单独设置尺寸与行高。
- 容器：地图全幅，行程抽屉为唯一主要浮层；避免卡片网格和多层嵌套面板。
- 圆角：主要抽屉20px；按钮和日期控制12–16px。
- 图标：统一线性图标，用于定位、导航、交通和详情，不使用装饰性图标。
- 动效：抽屉拖动、日期切换和地图聚焦使用150–240ms缓动；遵守 `prefers-reduced-motion`。

## 六日基准行程

### Day 1｜10月4日｜香港—关西机场—京都—城阳花火

- 08:20–13:05：香港飞往大阪关西机场。
- 机场入境取行李后乘 JR HARUKA 前往京都站。
- 京都站八条口 E1 乘 HOOP 巴士，在“祇园・四条河原町”下车，步行前往酒店。
- 预计16:00–17:00入住酒店。
- 17:00左右由祇园四条出发，经京阪线与 JR 奈良线前往长池站。
- 19:00–19:40：城阳秋花火2026，京都府立木津川运动公园。
- 花火为高风险可放弃项目：若航班或入境延误，页面提示不要赶场。
- 门票仅预售、限量8000张、现场无票；页面提供城阳市官方活动链接。

### Day 2｜10月5日｜祇园和服妆造—岚山

- 上午：酒店附近完成和服妆造。
- 11:00左右：从京都河原町经阪急线前往岚山。
- 中午至下午：渡月桥、天龙寺、竹林小径、嵯峨野街区。
- 根据和服店最晚归还时间安排返程；初版将“归还和服时间”显示为醒目提醒，不假设具体时刻。
- 不再追加金阁寺，避免穿和服时过度换乘与步行。

### Day 3｜10月6日｜京都东部—哲学之道

- 09:00：南禅寺、天授庵。
- 10:30：永观堂。
- 11:30起：哲学之道由南向北步行。
- 午餐与咖啡安排在哲学之道沿线。
- 下午：法然院、银阁寺；体力不足时跳过非核心小寺院。
- 该日保持东山北部单一区域，不与宇治互换，以免 Day 4 转城时路线逆向。

### Day 4｜10月7日｜宇治半日—大阪新世界

- 08:30前：京都酒店退房并寄存行李。
- 09:00左右：从祇园四条经中书岛转京阪宇治线前往宇治。
- 10:00–14:00/14:30：平等院、表参道、宇治川、宇治上神社或抹茶休息。
- 约15:00：返回祇园四条，取酒店行李。
- 15:30左右：祇园四条乘京阪本线至京桥，换大阪环状线至新今宫，再步行前往大阪酒店。
- 预计17:00–17:30入住 Grand Hostel LDK Osaka Shinsekai。
- 这套方案给宇治约4–5小时，足够完成核心路线，但不加入源氏物语博物馆等完整一日内容。
- 备选：若当天不想回酒店，京阪宇治站与祇园四条站都有投币柜，但数量有限；酒店寄存仍为默认方案。

### Day 5｜10月8日｜日本环球影城

- 06:45左右从大阪酒店出发。
- 从新今宫乘大阪环状线到西九条，换 JR 梦咲线到 Universal City。
- 目标是官方公布开园前60–90分钟抵达；USJ 可能早于标示时间开始入场。
- 全天游玩；页面提供官方营业时间、门票和项目休止链接。
- 若任天堂世界为重点，页面提醒提前处理门票、区域入场与 Express Pass，而不是到场后再决定。

### Day 6｜10月9日｜大阪市区—关西机场—香港

- 退房后将行李寄存在大阪酒店。
- 上午：新世界、通天阁周边。
- 中午至下午：日本桥电电城、难波、心斋桥购物；根据购物偏好后续调整地点。
- 16:30前返回酒店取行李。
- 17:00–17:30从新今宫或难波出发前往关西机场。
- 18:00–18:30抵达机场，预留国际航班值机、退税与安检时间。
- 21:30起飞，10月10日00:40抵达香港。
- 香港机场至皇岗的凌晨接驳以机场官方当日班次为准，页面只保存公共交通提醒，不展示家庭住址。

## Day 3／Day 4 取舍结论

不交换 Day 3 与 Day 4。哲学之道位于京都东北部，适合完整留在京都的一天；宇治在京都南侧，且京阪线可以从祇园四条经中书岛到宇治，再由京阪本线进入大阪。Day 4 返回酒店取行李会增加约一小时往返，但仍可在宇治停留4–5小时。把行李放在酒店比依赖数量有限的大型投币柜更可靠。

## 数据结构

地点和日程放在独立的 `itinerary-data.js` 中。每一天包含：

- 日期、标题、城市、地图初始中心和缩放级别。
- 地点数组：名称、经纬度、类型、计划时间、简述、详细提示。
- 可选字段：交通说明、预算、官方链接、票务链接、Google Maps 导航链接、天气敏感度、是否可放弃。
- 路线顺序：由地点 ID 数组生成地图连线。

修改地点时只编辑数据文件；界面、样式和交互无需重写。

## 技术方案

- 无构建步骤的静态 HTML、CSS、JavaScript，降低 GitHub Pages 部署和手机加载复杂度。
- Leaflet.js + OpenStreetMap 图层，通过 CDN 加载。
- 地点与路线由 JavaScript 数据驱动。
- 使用浏览器原生拖动/触摸事件实现抽屉，不引入大型框架。
- 外部导航和票务使用普通 HTTPS 链接。
- 不收集用户数据，不使用分析脚本、账户系统、数据库或服务端 API。

## 响应式与无障碍

- 重点验证 390×844 与 430×932 两类手机视口，以及桌面浏览器。
- 触控目标不小于44px，文本在200%缩放下不遮挡关键操作。
- 地图标记和日期控件提供可读标签、键盘焦点和选中状态。
- 地图不可用时，时间线仍能独立阅读和打开导航链接。
- 颜色之外再使用编号和文字表示当前站与路线顺序。

## 部署与隐私

- 初始化本地 Git 仓库，网站文件位于仓库根目录。
- 建议仓库名：`kyoto-osaka-2026-trip-map`。
- GitHub Pages 从默认分支根目录发布。
- 页面为公开链接；仅展示酒店名称、公共地点和旅行日期，不展示订单、证件、联系电话或家庭位置。
- 部署需要用户在 GitHub 登录；若本机没有 GitHub CLI，使用浏览器或安装 CLI 完成一次授权。

## 验证

- 本地启动静态服务器，使用浏览器检查全部六个日期切换、地图缩放、地点选中、抽屉拖动和外部链接。
- 对比已批准视觉概念与手机端浏览器截图，核对布局、颜色、字体、控件尺寸、抽屉比例和路线层级。
- 桌面与手机分别验证无横向溢出。
- 断开地图资源或模拟加载失败，确认文字行程仍可用。
- 发布后在 GitHub Pages 正式 URL 上复测核心交互。

## 已知风险与处理

- Day 1 花火受航班、入境、天气和门票影响：标记为可放弃，并显示预售票警告。
- Day 2 和服店与归还时间未确定：不生成虚假店铺坐标，等待后续数据更新。
- Day 4 宇治时间有限：优先平等院、表参道和宇治川，其他项目按体力删减。
- USJ 营业时间可能变更且可能提前入场：页面链接到官方日历，显示“出发前复核”。
- 地图与路线是参考坐标，不代替当天官方交通公告。
